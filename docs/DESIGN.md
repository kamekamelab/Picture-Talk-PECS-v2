# PTP v2 設計と初期版の範囲

## 方針

既存の Picture-Talk-PECS を変更しない独立したリポジトリ。画面・コード・保存領域を分離する。学習の中心は「カードを選ぶ → 相手に渡す → 相手が受け取る → 実際の物・活動につなげる」。タップや正解アニメーションだけで交換成立としない。

## 画面

先生用：学習の準備、カード、学習記録、バックアップ、設定。生徒用：1枚のカード、渡す場所、相手に見せる画面、受け取り後の画面。Phaseや記録件数は生徒用に出さない。設定は長押しと任意PINで誤操作を防ぐ。PINは暗号化ではない。

初期版はタップ操作、文字の表示切替、日本語、静かな配色。自動読み上げは導入しない。録音・ドラッグ・カード複製・配置編集は次段階で検討する。

## Phase

| 段階 | 指導で重視すること | 実装状況 |
| --- | --- | --- |
| 1 | 1枚のカードを相手に渡して要求を伝える | 初期版。受け取り時に未評価として保存し、先生が支援の有無を記録 |
| 2 | 実際に距離を移動し、相手・場所を変えて伝える | 未実装。画面内移動で達成と判定しない |
| 3 | 複数から欲しい物のカードを選ぶ | 未実装。カードと実物の対応を先生が確認 |
| 4 | Sentence Strip上に要求表現と物のカードを組み合わせ、帯全体を交換 | 未実装。日本語語順・個別設定に対応予定 |

アプリはPECSの考え方を参考にした教育用の補助であり、正式な指導手順・研修の代替とはしない。Phase 1・2は紙カードと併用できる設計を継続する。

## データ構造

IndexedDB `picture-talk-pecs-v2` の `app` ストア、キー `state` に保存する。単一のreadwriteトランザクションが完了してからメモリー上の状態と画面を更新し、保存失敗時に見かけだけ成功にしない。旧アプリの `ptp_*` localStorageには触れない。

- `schemaVersion`：保存・バックアップの版番号。
- `profile`：任意の呼び名、現在の学習カードID。初期版は1つの学習設定。
- `cards`：ID、表示文字、カテゴリ、マーク、画像Data URL。
- `records`：ID、受け取り日時、Phase、カードID、当時の文字と呼び名、支援の有無。カードを編集・削除しても過去の意味を保持。
- `settings`：文字表示、PINのsaltとPBKDF2ハッシュ。
- `lastBackupAt`：書き出し操作日時。ダウンロード完了・外部保存の保証ではない。

呼び名と写真は個人情報になり得る。実名登録は求めず、実データをリポジトリや開発Issueへ含めない。初期版ではメモ・複数の学習者プロフィール・集計グラフは未実装。

## バックアップ

JSONの `format` と `schemaVersion` を確認し、カードID重複、画像URL、記録、PIN設定、総サイズを検証。未知のキーを除去してから内容確認画面を表示する。実行すると現在のデータを一括置換。書き込み失敗時は元のトランザクションを保持する。PIN付きバックアップの復元後は先生用画面をロックする。

ファイルは暗号化しない。端末の「ファイル」や管理下の保存先で保存を確認する。一般公開リポジトリにバックアップを入れない。データ総量を24MBに制限し、25MBの復元上限内で書き出せるようにする。

## PWAと配信

依存のないHTML/CSS/ES Modules。`dist/` を静的HTTPS配信できる。全アセット・manifest・Service WorkerのURLは相対指定。オフラインキャッシュはアプリ本体だけで、画像・学習データはIndexedDBに保存。

Service Workerは必須ファイルの取得が全件成功してからインストールされる。新しい版は開いた画面を強制更新しない。公開時はコード変更に合わせてキャッシュ名を更新する。

第三者CDN、外部フォント、解析、広告、クラウド音声、画像検索、自動同期なし。CSPで配信元以外への通常通信を制限。オンラインの取得・更新時には配信元への通信が発生し、GitHub Pagesを使う際はGitHubのアクセスログがある。CSPは同一配信元の全アプリ間の厳密な分離ではない。

## 今後の保存方式

初期版は小規模利用を対象に、状態一式を保存する。写真や記録が増える段階では画像Blob・カード・セッションを別ストアに分け、保存量・書き込み頻度とバックアップ分割方式を設計し直す。版変更時には既存バックアップの移行を用意する。
